# v1.0 测试报告

## 自动化范围

- 确定性算法：EXIF、透明格、裁剪、三种尺寸、三档颜色、色板合法性、孤立格、PNG 与材料一致性；
- 40 图回归：人物、宠物、物品、插画、特殊图片各 8 张，固定记录预期主体、风险、尺寸和颜色；
- 人工评审材料：同一 40 图逐例生成原图、12 像素拼豆效果、24 像素单元编号网格、技术统计与 SHA-256 清单；离线评分、进度保存、严格最终 CSV 导出，旧轮次不可覆盖；
- 业务集成：四类会员、权限、任务状态、张数预留/使用/释放、并发抢占、失败重试、配置快照；
- AI：严格 Schema、图片内指令防护、启用选项限制、超时、非法结果、规则降级、日志脱敏；
- 真实模型评测工具：显式费用确认、2～3 个唯一模型、10～15 张统一图片、服务能力预检、单次失败隔离、脱敏 CSV 和高级输出留档；
- 非计费模型预检：只调用模型列表，不上传图片或生成内容；未知供应商/模型拒绝猜测，报告不可覆盖且不包含密钥或私有服务地址；
- 高级创作：权限、三类稳定操作、主体保留、视觉复查、父子版本、免费参数调整、故障保护；
- 图纸库和导出：所有权、软删除、PNG 字节一致、30/50/70 PDF 页数/中文/材料/A4，并用 Poppler 实际渲染像素；
- 端到端：Chromium 桌面与 390px 手机视口完成登录、上传、分析、设置、生成、三结果标签、预览、保存和图纸库；额外用纯键盘完成同一主流程，并用真实浏览器验证损坏文件、主体重选、张数不足保留设置、免费重试成功、最终失败释放和保存失败后重试；
- 可用性走查证据：固定六项外部真人任务、匿名测试者、日期、设备、完成状态、协助次数、用时、困惑严重度、观察和记录人硬校验；模板 pending、缺项、重复、未完成、重大困惑或过期记录不能通过；
- 运维：健康检查、超大文件、密钥日志脱敏、演示数据、迁移检查、Ruff 和 Django system check；目标 CI 中验证 PostgreSQL、Redis、4 个并发 Celery 往返以及 Worker 离线入队后的重启恢复。
- 发布门槛：首次外部真人可用性走查、40 图人工评分完整性、主体可辨认率、严重主体错误率、可制作率、高级创作符合率、重试率、错误扣减、未完成任务、P0/P1 和部署冒烟统一硬校验；运营指标从数据库自动取数，部署从 7 天内 HTTPS JSON 证据取数。
- 实体制作证据：人物、宠物、物品三类 30×30 图纸，计划/实际豆数、差值、制作时长、熨烫结果、评审人、日期、有效成品图片和路径边界硬校验。
- 部署冒烟工具：HTTPS、预期主机、健康页、产品首页、指纹 CSS/JavaScript、HSTS、点击劫持、MIME 嗅探、Referrer Policy、跨域重定向和不可覆盖 JSON 证据。
- 性能基线：当前存储写入/读回、规则分析、70×70/36 色图纸与两类 PNG 生成、完整分页 PDF 导出，固定阈值、最大样本判定和不可覆盖 JSON 证据。
- 计划追溯：222 个任务编号全量、唯一覆盖，11 个未编号完成门槛独立审计，证据路径存在性和外部待验收防伪造校验。
- 内部演示：从真实 Chromium 桌面主流程录制不可覆盖 WebM，再由 Chromium 检查可播放视频轨、1280×900 分辨率和有效时长。

## 40 图固定集

测试图由 scikit-image 随依赖发布的合法样例（人物、人脸、猫、马、咖啡、硬币、时钟、火箭、图形、文字、透明图和复杂场景等）确定性裁剪和风险变换，避免版权不明的网络图片和二进制仓库膨胀。每类编号 01–08；07 为低对比或复杂风险，08 为小尺寸或特殊风险。尺寸和颜色按 30/12、50/24、70/36 循环。每次全量测试都会重新生成正式网格并检查颜色上限、材料合计和尺寸。

## 验收结论

自动化通过标准是零失败、零跳过、零 xfail。任何失败必须修复实现或明确修复错误测试数据，不允许删除测试或放宽业务标准。最终测试命令和实际数量记录在交付说明中。

作品集 Demo 与商业发布采用两个明确分开的门槛。`check_portfolio_demo` 验证无需外部服务即可稳定展示的页面、会员、演示账号、素材、离线分析、高级模拟创作和正式图纸核心；`check_release_quality` 只在未来需要主张真人效果、实体可制作性和公网生产就绪时使用。后者保持 pending 不会阻止作品集交付。
