# AI 图片分析设计与选型（M5）

## 结论

图片分析采用统一适配层。后台可以切换供应商和模型，任务创建时保存路由快照；页面和图纸算法不直接依赖任何模型 SDK。

- 本地及 CI：`rules / rule-analysis-v1`，零外部成本，可确定性降级；
- 首选真实模型：`openai / gpt-5.6-luna`，面向高频、成本敏感的结构化图片分析；
- 质量对照：`gpt-5.6-terra`；
- 高质量参考：`gpt-5.6-sol`，只用于难例评测，不作为默认路径。

模型名称只是首版配置值，不是写死的商业决策。管理员可在 `model_routes.analysis` 新建配置版本并启用；已经创建的任务继续使用自己的快照。

## 统一评测方法

候选模型使用相同的十张固定回归图（人物、宠物、物品、插画、透明图、低分辨率、低对比度、过暗、过亮、文字干扰）和同一个 `analysis-v1.0` Prompt。记录以下字段：

1. JSON Schema 首次通过率；
2. 主体描述、数量和区域是否正确；
3. 风险是否诚实表达，低可靠结果不得伪装为确定答案；
4. 推荐值是否只来自 30/50/70、12/24/36 和启用的背景选项；
5. 中文说明是否简短可读；
6. 延迟和后台模拟成本。

自动化测试覆盖同一输出契约、非法字段、超时重试、图片内指令、规则降级及不扣生成张数。真实供应商的延迟和效果数据应在部署环境配置密钥后写入新的评测记录，不能用模拟数据冒充线上结论。

## Prompt 与安全边界

Prompt 版本固定为 `analysis-v1.0`。图片中的文字一律视为被分析内容，不能改变系统任务；模型不能推荐后台未启用的选项；最多显示三个主要问题。所有返回值在写入数据库前经过 Pydantic 严格校验，额外字段、非法枚举、越界主体框都会触发降级。

## 失败、重试与成本

真实模型最多尝试两次，后台可配置且代码硬上限为三次。配置错误、超时、限流、网络错误和非法输出均写入 `ModelCallLog`。真实模型最终失败后使用规则分析；规则分析也失败才把任务标为失败。分析阶段从不预留或消耗生成张数。

## 主体分割策略

首版不为每张图强制调用专用分割模型。只有低置信度或多主体结果才保存可重新选择的主体蒙版；背景移除仍有确定性算法兜底。蒙版或分割失败时，用户可以保留背景继续，不阻断基础生成。这避免为不需要去背景的图片增加成本和延迟。
