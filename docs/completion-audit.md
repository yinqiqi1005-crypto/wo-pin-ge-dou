# 开发计划完成度审计

本文件按 `development-plan.md` 的 M0–M9 逐项区分三种状态，避免把模拟测试等同于现实世界验收。

- **已实现并自动验证**：代码、页面或文档存在，且对应自动测试通过；
- **已实现，待目标环境验证**：实现和自动测试已完成，但当前电脑缺少计划指定的真实服务；
- **待人工或外部验证**：必须由真实模型、真人、实体材料或公网环境完成，自动测试不能代替。

## 本机最终验证命令

```bash
uv run ruff check .
uv run ruff format --check .
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py check
uv run pytest
```

生产安全检查额外使用 `DEBUG=false`、强随机临时密钥、HTTPS Cookie、SSL 跳转和 HSTS 参数运行 `manage.py check --deploy`。静态资源经 manifest 模式重新构建，并由 Gunicorn 双 Worker 实际返回健康页、首页、指纹 CSS 与 JavaScript。

## 不能由自动化冒充的发布门槛

以下指标在真人完成 40 图观察表前不能标记为通过：主体可辨认率至少 85%、严重主体错误率低于 5%、可制作比例至少 85%、高级创作符合度。实体拼豆制作和公网部署同理。`test-results-40.csv` 中的 `human_review` 因此保持为 `pending`。

真实 PostgreSQL/Redis/Celery 验收由 CI 的 `infrastructure` 作业执行。命令同时检查 PostgreSQL 查询、Redis Ping 和 4 个并发 Celery 往返；当前电脑只有 SQLite，直接运行会明确失败，不会自动降级并伪装通过。
