## 交付结论

**求职作品集 Demo 已完成并可运行。** 独立就绪检查已验证页面、四档会员、三个演示账号、三张素材、离线分析、高级模拟创作路由和正式图纸生成，证据见 [`portfolio-readiness/local-2026-08-08.json`](portfolio-readiness/local-2026-08-08.json)。真人调研、真实付费模型、实体制作和公网部署属于未来商业验证，不再阻止作品集交付；它们仍在下表保持未验证，以避免夸大项目经历。

本文件按 `development-plan.md` 的 M0–M9 逐项区分三种状态，避免把模拟测试等同于现实世界验收。

机器可检的详细映射位于 [`development-plan-traceability.json`](development-plan-traceability.json)：它必须唯一覆盖开发计划全部 222 个任务编号，同时审计 11 个未编号里程碑完成门槛。自动测试会拒绝缺项、重复项、不存在的证据路径，以及把必须依赖外部证据的项目标记为本机已验证。

- **已实现并自动验证**：代码、页面或文档存在，且对应自动测试通过；
- **已实现，待目标环境验证**：实现和自动测试已完成，但当前电脑缺少计划指定的真实服务；
- **待人工或外部验证**：必须由真实模型、真人、实体材料或公网环境完成，自动测试不能代替。

## 本机最终验证命令

```bash
uv run ruff check .
uv run ruff format --check .
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py check
uv run pytest
```

生产安全检查额外使用 `DEBUG=false`、强随机临时密钥、HTTPS Cookie、SSL 跳转和 HSTS 参数运行 `manage.py check --deploy`。静态资源经 manifest 模式重新构建，并由 Gunicorn 双 Worker 实际返回健康页、首页、指纹 CSS 与 JavaScript。

## 不能由自动化冒充的发布门槛

以下指标在真人完成 40 图观察表前不能标记为通过：主体可辨认率至少 85%、严重主体错误率低于 5%、可制作比例至少 85%、高级创作符合度。实体拼豆制作和公网部署同理。`test-results-40.csv` 中的人工字段因此保持为 `pending`。

`manage.py prepare_human_review` 会从固定合法样例生成每例的原图、拼豆效果和 24 像素单元编号网格，共 120 张对照图，并保存参数、材料数和 SHA-256 清单。离线页面提供逐项评分、本机进度保存、进度 CSV 和最终 CSV；存在任何 `pending` 时最终导出按钮保持禁用。输出目录采用排他创建，不能覆盖旧轮次。本机已生成 `media/human-review/round-3/index.html`，但尚未由真人填写评分。

M3 要求的内部演示已由同一条真实 Chromium 主流程录制为 [`demo-recordings/basic-flow.webm`](demo-recordings/basic-flow.webm)。自动测试会用 Chromium 重新打开该文件，校验有效视频轨、1280×900 分辨率和非零时长。

`manage.py check_release_quality` 会拒绝任何未完成的人工评审，并同时校验首次外部真人六任务可用性走查、文件生成成功率、材料一致性、上述真人指标、至少 3 个高级创作案例、自动重试率、错误扣减、未完成任务、P0/P1 问题和部署冒烟。重试与扣减指标直接从数据库任务/张数流水计算，P0/P1 来自版本化问题表，部署必须提供 7 天内的公网 HTTPS JSON 证据；命令不再接受这些结论性数字或 `passed` 布尔值。

同一命令还会读取 `docs/physical-validation.csv`，强制人物、宠物、物品各一张 30×30 实体作品；实际豆数、与计划差值、制作时长、熨烫结果、评审人、日期和有效成品图片缺一不可。模板仍为 `pending`，没有实物时无法通过。

`manage.py smoke_deployment` 对真实域名验证 HTTPS、最终主机、健康页、产品首页、指纹静态资源和关键安全头，并使用排他创建保存 JSON 证据。它已通过模拟响应测试，但尚未对公网地址运行，不能提前把 M9-33 标为通过。

真实 PostgreSQL/Redis/Celery 验收已经在全新临时本地环境运行：PostgreSQL 16.6、Redis 7.2.7、Celery 5.6.3 非 eager Worker 完成 10 个并发往返；随后停止 Worker，在离线状态入队，启动替代 Worker 并取回同一任务结果。不可覆盖且不含连接地址/密码的原始证据位于 [`infrastructure/local-2026-08-08.json`](infrastructure/local-2026-08-08.json) 和 [`infrastructure/worker-recovery-2026-08-08.json`](infrastructure/worker-recovery-2026-08-08.json)。同样的协议已在 GitHub Actions 运行 `31212392462` 中通过；普通质量作业与真实基础设施作业均成功，结构化记录位于 [`ci/github-actions-2026-08-08.json`](ci/github-actions-2026-08-08.json)。
